# Toolkit library gaps

Parts and tokens the Toolkit frames need that the component library
(`@eshelton328/component-library-1701`, the build installed in this
worktree) cannot draw. Each gap goes to the library in a batched PR
through the `library-gap-filler` agent; bridge-coord releases it
(d-104). Until then the screen uses the part named under "Used now", and
the frame's `deviations.md` lists the difference.

Library #115 (beta.14) closed the rail item height (`NavRail` items 50 px
high and 56 px apart, as Figma's) and the More drawer's item spacing (M04's
four item icons pass the position check). Library #126 (beta.21, used
since beta.25) closed the item tab spacing and the item tab selected tone:
`ToolkitItem` sets `ItemTabs tone="accent"` on every layout, so the
selected tab's label is cyan as Figma's, and `density="compact"` on a
tablet and the phone, so the tabs start at the list's edge with 10 px
sides and Evals ends inside the phone's screen. The selected tab's
outline stays `border.selected` at half alpha, since no solid selected
token exists (d-050). Library #130 (beta.26) added AppShell
`tabBarOverlay`: on a tablet and the phone the tab bar lies over the
page, so text that Figma draws under the bar (M02, M12, M20, M22, T01,
T10) is under it in the render too and passes the text check. Library
#132 (beta.28) closed the code line wrap: `CodeLines` `wrap` wraps a
long line of M22's script in the text column, its number on the first
line, so no line is cut and the code does not scroll sideways. A wrapped
line is 32 px high (two lines of the 12/16 mono style on the 4 px grid,
d-090) where Figma's is 34; no line-height token has 17 (d-050), so
M22's `deviations.md` records the shorter box. Library #133 (beta.30)
added the flow connectors `FlowLine`, `FlowBranch` and `FlowLoop`, and
#137 (beta.31) ends each tip 2 px before its target and the loop's tip
4 px before the stop: the workflow page (D13, T08, M09) draws every
connector with them, and the flow by phase (D08, T18) draws its straight
arrows with `FlowLine`. Library #153 (beta.42) closed the item tab
width: an `ItemTabs` trigger has no border until it is selected, so each
tab is within 1.1 px of Figma's width and starts within 2 px of its x
(the desktop list's 2 px padding, a tablet Container's 24 px side).
Activity ends at 988.3 against 989 on the desktop and 462.3 against 463
on a tablet, and on the phone the selected Evals (M18, M27 to M30) is
319.5 to 376.4 against 321 to 378, inside the list's end, so its
outline is whole. Library #166 (beta.47) closed the Toolkit card height:
`Card metaSpacer` puts the counts 34 under the description, so each D1
card is 148 high against Figma's 150 and every card passes the position
check. It closed the Toolkit row (tablet) too: `Card padding="compact"`
with the counts as `trailing` makes T1's row 60 high against 59, with the
tile 13 in and the counts centred at its end. Measured on beta.47, the
More drawer's first focus matches Figma too: the drawer opens with the
focus on its sheet, whose outline is transparent, so no ring shows, as
Figma draws none on M4. The rows below record what #166 narrowed. Library beta.67 closed the
long KPI caption (`KpiTile captionLines`), the Evals chart's size and
width on a tablet and the phone (`GroupedBarChart size` and `width`) and
the ✗ and ✓ marks in React text (`Glyph`); the KPI tile, Evals bar chart
and Symbol glyphs rows say what remains. The workspace installs
`1.0.0-beta.67`.

Library #211 (beta.69) closed four map rows. `MapGraph nodeDensity="compact"`
draws T2's and M11's 140 × 30 nodes with a 12 px icon and the name 27 px
in, so `pr-description` shows whole (Map node 140 px);
`edgeEnd="none"` ends their links at the node's edge with no dot (Map
link ends); `minimap` draws the phone's small map in the window's top
right corner (Map minimap); and `MapSelectionCard density="compact"`
with `linksLabel` and `onLinks` is M11's card: the counts as arrows at
the title row's end, Show links and Open writer on one row and no close
button, 366 × 90 as Figma's (Map selection card (phone)). Show links
opens the item on its Links tab (`openLinks`), since M11's note sends it
to M3, a proposal with no frame.
